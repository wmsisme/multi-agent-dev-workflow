# 安全管控与失败模式手册

Agent 自主循环的系统，风险和普通程序不一样：**它不会报错退出，它会"努力地"把成本烧光**。这份手册是本编制在真实运行中定下来的闸门与教训。

## 一、四道闸门

| # | 闸门 | 阈值 | 触发后行为 |
|---|---|---|---|
| 1 | **迭代上限** | 最大 5 轮 | 立即中断，返回当前最佳结果 |
| 2 | **总耗时** | 120 秒 | 超时中断 |
| 3 | **评分趋势** | 连续 2 轮提升 < 0.01 | 判停滞，提前终止 |
| 4 | **评分下降** | 任意一轮下降 | 立即中断，**回退上一轮最佳结果** |
| 5 | **循环模式** | 连续两轮输出余弦相似度 > 0.95 | 判定原地打转，直接中断 |

**中断不等于抛异常**：停止时返回 `{最终结果, 监控数据, 中断原因}`，调用方任何情况下都能拿到东西。这是"优雅降级"的实现方式。

> ⚠️ **阈值是经验值不是常数**：5 轮 / 120 秒来自一个具体系统的实测。换场景请先估单轮耗时与成本再定上限。

## 二、六种失败模式（都真实踩过）

### 1. Agent 既当运动员又当裁判
**现象**：同一个 Agent 既出题又评分，分数系统性偏高，越来越"自我感觉良好"。
**根因**：它知道标准答案是自己写的，会顺着自己的思路判分。
**对策**：拆成两个 Agent + 上下文隔离；标准答案尽量走独立来源（人工队列最佳）。

### 2. 上下文互相污染
**现象**：后一步的结论明显被前一步的思路带偏。
**根因**：所有步骤共享一个上下文窗口，前一步的推理过程留在了后面步骤的视野里。
**对策**：子 Agent 独立上下文；跨 Agent 只传**固定字段**的结构化结果，不传推理过程。

### 3. 死循环 / 在原地打转
**现象**：迭代一直跑，每轮输出看起来不同但实质一样，成本线性上涨。
**根因**：没有终止条件，或终止条件只判"成功"不判"没进展"。
**对策**：迭代上限 + 耗时上限 + 评分停滞早停 + **输出相似度检测**（余弦 > 0.95 判循环）。

### 4. 越改越啰嗦（信息膨胀）
**现象**：每轮返工都往里塞内容，最后主题被噪音淹没。
**根因**：返工指令只说"要加什么"，没说"不能加什么"。
**对策**：让诊断 Agent **明确列出下一轮不应添加的内容**——这条反向约束是长文生成任务的关键。

### 5. 写入留下半写数据
**现象**：向量库出现"看起来写了但搜不到"或"写了一半"的脏数据。
**根因**：批量写入没有校验与回滚；向量维度 / 元数据 / 索引不一致。
**对策**：写前校验 → 分批写入并逐批校验 → **写后抽样检索验证** → 失败回滚不留半写数据。

### 6. 评分口径跨轮漂移
**现象**：同一份产出的分数今天 0.8、明天 0.6，历史数据没法比较。
**根因**：评分标准是"感觉"，没固定分制、没固定维度、没固定输出格式。
**对策**：分阶段固定维度 + 固定分值区间（1–10）+ **强制 JSON 输出** + 把评分标准提前到出题时（关键点清单）。

## 三、权限设计（最小必要）

| 能力 | 给谁 | 说明 |
|---|---|---|
| 写知识库 / 向量库 | 只给知识库写入 Agent | 能长期改变系统知识的，只此一个 |
| 执行命令 / Shell | 尽量不给；不得不给时只给写文档类 Agent | 爆炸半径最大的一项 |
| 通用文件写 | 文档生成 Agent、写入 Agent | 其余 Agent 只读 |
| 派发子任务 | 主 Agent / 编排 Agent | 避免子 Agent 无限递归派活 |

## 四、上线前的检查清单

- [ ] 每个 Agent 的 **description（何时被调用）** 都填了——这是编排器匹配任务的唯一依据；
- [ ] 每个 Agent 的**工具清单**已按最小必要配好，写入/命令类工具没多给；
- [ ] 迭代上限、耗时上限**在代码里也有一份**（不能只靠提示词，模型说了不算）；
- [ ] 中断时**必定返回最佳结果 + 中断原因**；
- [ ] 评分 Agent 的输出能被程序解析（JSON schema 校验）；
- [ ] 出题 Agent 的**关键点清单**抽样人工核对过；
- [ ] 写入 Agent 的**写后抽样检索验证**跑通了一次；
- [ ] 有一份**人工标准答案队列**（哪怕只有 10 条）用于校准模型评分。
